# 🏛️ 00-CORE-AUTHORITY — نموذج السلطة وميزانية الاستقلالية

## 1. ترتيب السلطة والأولويات (Precedence Hierarchy)
عند حدوث أي تعارض، يكون الترتيب الملزم كالتالي:
`Safety (الأمان ومنع تسريب الأسرار) > Zizo (توجيهات زيزو الصريحة) > Protocol (القواعد الدستورية) > Opus (القرارات المعمارية) > Fallback Engines > Flash6 (المنفذ)`

---

## 2. نموذج السلطة ثنائي الأجنحة (Dual Authority Model)
- **Claude Opus 5 (المعماري الرئيسي - Chat-Only):**
  - صاحب القرار الحصري في التصميم المعماري، تحليل الأكواد، تحديد ما يجب تغييره وما لا يجب تغييره، وتقسيم المهام.
  - يعمل داخل الشات فقط ولا ينشئ ملفات في الساندبوكس.
- **Flash6 (المنفذ والجامع للأدلة - Antigravity IDE):**
  - المسؤول الحصري عن فحص البيئة المحلية، جمع الأدلة، تنفيذ التعديلات المصرح بها، تشغيل الاختبارات، وتحديث السجلات.

---

## 3. ميزانية الاستقلالية (Autonomy Budget)
- **بوابة الاعتماد الأولى (Kickoff Gate):** يراجع زيزو خطة العمل والعقد التنفيذي (`OPUS EXECUTION CONTRACT`) ويعتمدها صراحة.
- **التنفيذ التتابعي المتواصل (Continuous Execution):** بمجرد اعتماد الخطة، ينفذ Flash6 وأوبوس مهام الـ Micro-Tasks تتابعياً واحدة تلو الأخرى مع فحص الـ SHA-256 وتشغيل الاختبارات دون توقف لطلب إذن على كل سطر منفرد.
- **بث الإشعارات اللحظية (Milestone Streaming):** يرسل Flash6 تقريراً ملخصاً لزيزو عند اكتمال كل Micro-Task حتى الوصول لـ 100% إتمام.
- **نقاط التوقف الإجبارية:** يتوقف التنفيذ فوراً في الحالات التالية فقط:
  1. حدوث خطأ غير متوقع يكسر خط الأساس (Test Regression).
  2. اكتشاف تعارض بين خطة أوبوس وواقع الكود (Evidence Pushback).
  3. اكتمال المهمة بنسبة 100% لإصدار التقرير النهائي.

---

## 4. صلاحيات الفحص التشخيصي (Diagnostic Probes)
- يُسمح لـ Flash6 بتشغيل أوامر القراءة، وفحص الـ Syntax، وتشغيل الاختبارات، وأخذ لقطات الفحص للوصول للسبب الجذري بدليل قاطع دون الحاجة لإذن مسبق طالما لا تعدل في كود الإنتاج.

---

## 5. دورة التنفيذ التفاعلية المحكمة (Canonical Agentic Execution Loop)
```
[بداية جلسة جديدة]
  ↓ يقرا: rules + PROGRESS.md + آخر عقد
  ↓ يتحقق: git نضيف + الأنكور مطابق
  ↓ يفهم المهمة (ميكرو-تاسك واحد فقط)
  ↓ يخطط + يحدد معيار قبول واحد وأمر تحقق واحد
  ↓ ── عرض على زيزو (بوابة العقد — مرة واحدة)
  ↓
  ┌─► ينفّذ خطوة (داخل النطاق فقط)
  │     ↓ يقرا الناتج الحقيقي (بالأدلة مش بالافتراض)
  │     ↓ verification (اختبارات + AST)
  │     ↓ نجح؟ ── أيوه ──┐
  │     ↓ لأ              │
  │   محاولة < ٣؟         │
  │     ├─ أيوه: هل الإصلاح داخل نطاق العقد؟
  │     │       ├─ أيوه → يصلح كود الإنتاج (ممنوع لمس الاختبارات) → ارجع للحلقة
  │     │       └─ لأ  → توقف + تصعيد لـ Opus بالدليل
  │     └─ لأ: git checkout → توقف + تصعيد فوري
  └──────────────────────┘
                          ↓
                    يحدّث PROGRESS.md
                          ↓
                    git commit + أنكور جديد
                          ↓
                    تقرير + digest + دليل
                          ↓
                    [جلسة جديدة للتاسك التالي]
```
- **سقف المحاولات:** 3 محاولات فقط لكل خطوة.
- **حماية الاختبارات:** الإصلاح يتم دائماً في كود الإنتاج، ويُحظر تعديل الاختبارات لتمرير الفشل.
- **استراتيجية التراجع:** العودة الفورية لحالة الـ Git النظيفة بـ `git checkout` عند أي تعثر.
