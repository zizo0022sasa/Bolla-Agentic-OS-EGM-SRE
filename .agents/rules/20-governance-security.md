# 🔒 20-GOVERNANCE-SECURITY — الحوكمة والأمان والنزاهة

## 1. بوابة تنقية الأسرار (P0 — Secret & Credential Redaction Gateway)
- **إلزامية التطهير:** يجب فحص وتنقية أي كود أو سجل أو رسالة يتم إرسالها لأوبوس أو أي محرك خارجي واستبدال كافة المفاتيح، التوكنات، كلمات المرور، ومتغيرات `.env` بـ `<REDACTED>`.
- **حظر تام للتسريب:** يُمنع إرسال أي بيانات اعتماد حقيقية عبر الشات.

---

## 2. نقاء الكود وفصل البرومبتات (RULE 16 — Code Purity)
- ملفات بايثون (`.py`) مخصصة 100% لمنطق الإنتاج البرمجي فقط.
- كافة التعليمات، البرومبتات، المبادئ، والخطط توضع حصرياً في ملفات Markdown (`.md`) أو Text (`.txt`).

---

## 3. الشات فقط وحظر الساندبوكس (RULE 24 — Strict Chat-Only)
- أوبوس يقدم كافة تحليلاته، أكواده، والـ diffs كنصوص منسقة في الشات مباشرة.
- يُحظر على أوبوس إنشاء أو حفظ ملفات في الساندبوكس الخاص به.
- Flash6 هو المنفذ الحصري لكتابة وتعديل الملفات محلياً.

---

## 4. حق الاعتراض بالدليل البرمجي (P1 — Evidence-Based Pushback)
- إذا اكتشف Flash6 أثناء التنفيذ دليلاً برمجياً، أو خطأ في الـ Syntax، أو واقعاً يناقض افتراضاً معمارياً في خطة أوبوس، يتوقف Flash6 فوراً ويعرض الدليل الحرفي على أوبوس لتصحيح الخطة بدلاً من التنفيذ الأعمى.

---

## 5. فحص بصمة الـ SHA-256 وسلامة الملفات (RULE 23)
- فحص وحساب بصمة الـ SHA-256 لأي ملف مستهدف قبل التعديل (`SHA_BEFORE`) وبعد التعديل (`SHA_AFTER`).
- توحيد المعايير: UTF-8 بدون BOM، وتنسيق أسطر موحد.

---

## 6. استراتيجية التراجع والـ Git (Rollback Strategy)
- قبل أي تعديل على الكود، يجب أن تكون شجرة العمل نظيفة (`git status --porcelain`).
- كل Micro-Task ينتهي بـ Git Commit فوري مستقل.
- في حالة فشل التحقق وعدم القدرة على الإصلاح: يتم التراجع فوراً باستخدام `git checkout HEAD -- <file>`.

---

## 7. نطاق الاختبارات والتطوير الداخلي (RULE 31)
- كافة السكربتات والأدوات ومنظومات الأتمتة في بيئة العمل مخصصة حصرياً لبيئة الاختبارات التكاملية الداخلية (Internal Integration Testing) والتطوير المحلي وضمان الجودة المعملية (Development Pipeline).

---

## P0-FIXTURES — Recording Sanitization
- No fixture may be written to disk before passing `secret_guard.py`.
- No commit may include a fixture containing a live token, cookie, or credential. Violation = delete fixture + re-record sanitized.
